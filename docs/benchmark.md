# Benchmark

cssdiff checked against Chrome's `getComputedStyle()` on 24 random CSS edits to a real site, and timed. The harness is in [`bench/`](../bench); running it is described in [development.md](development.md).

## Setup

| | |
|---|---|
| Corpus | 28-page static documentation site (Astro Starlight build), 10,509 elements, 4 stylesheets |
| Viewports | 375x812, 768x1024, 1440x900 |
| Edits | 24, generated by `bench/mutate.py` with seed 7: changed colors, lengths, keywords and media-query breakpoints, deleted declarations, across all 4 stylesheets |
| Reference | Chrome for Testing 156 headless shell via Playwright, JavaScript disabled, one browser and tab reused across pages, scrollbars hidden |
| Machine | Intel i7-12700, 6 cores |

For each edit, both engines compare the original site with the edited copy. A change is a `(page, viewport, element, property)` tuple. Chrome's own run-to-run noise was measured by dumping the unmodified site twice: 0 values differed.

## Accuracy

Properties whose `getComputedStyle()` value is a layout *used* value (sizes, margins, paddings, insets, `transform-origin`, `perspective-origin`, grid track sizes) are left out of the score: cssdiff compares computed values, and these change with layout, not with the cascade.

| | Result |
|---|---|
| Edits where both engines agree on changed / unchanged | 24 / 24 (7 changed, 17 unchanged) |
| Changes found by Chrome | 549 |
| Found by cssdiff | 549 (recall 100%) |
| Reported by cssdiff only | 0 (precision 100%) |

The 17 unchanged edits hit print-only rules, breakpoints between the tested viewports, overridden declarations or selectors matching no element. Chrome reported 18,398 further changes in layout used values (`width`, `transform-origin`, `perspective-origin`, `height`, insets, auto margins); `--mode used` covers those, with fonts as the main source of divergence.

### Engine agreement

On the unmodified site, 93.9% of 7.9 million `(element, viewport, property)` values are byte-identical between Chrome and cssdiff. The rest are engine differences that are the same on both sides of a diff:

| Kind | Example (Chrome → cssdiff) |
|---|---|
| Layout used vs computed value | `width: 343px` → `auto` |
| User-agent stylesheet | `svg { overflow: hidden }`, `<option>` display, link `cursor: pointer` |
| Serialization | `text-align: start` → `left`, `14.4px` → `14.4063px`, `matrix(…)` → `rotate(90deg)` |
| System colors and fonts | `color-scheme: dark` canvas text, `"Times New Roman"` → `serif` |

## Speed

```sh
hyperfine -N --warmup 2 --runs 15 \
  'cssdiff -b /base site edited' \
  'cssdiff -j 1 -b /base site edited'
```

| | Wall time | Max RSS |
|---|---|---|
| cssdiff, 6 threads | 417 ± 38 ms | 93 MB |
| cssdiff, 1 thread | 1.58 ± 0.07 s | 29 MB |
| Chrome, one version (median of 33 dumps) | 71 s | |

Comparing two versions in Chrome takes two dumps, about 140 s against cssdiff's 0.42 s. Each Chrome dump reads 249 properties of every element at 3 viewports through `getComputedStyle()` and serializes them out of the page; cssdiff reads values in-process and serializes each shared style once.
